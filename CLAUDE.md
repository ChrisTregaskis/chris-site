# chris-site — the charter

This file orients any Claude session that opens this repo. Read it first, then `CLAUDE.local.md` (gitignored, machine-local) for the scratch pad, HQ sync rule and the named anonymisation list.

## What this is

Chris Tregaskis's portfolio site, served at `chris-tregaskis.uk` (with `www.` redirecting). One long-scrolling React page in one dark look, Night chapters (no theme switch): a hero, three numbered case studies, each on its own full-bleed tone that fades into the next (Wayfinder with its interactive isometric figure, which comes apart into numbered pieces part by part, its live chat demo and How it was built lane; a physio and wellness platform, with a tenant-isolation figure and a leak test that plays itself; Badass Burpees), About and Contact, under a sticky top bar (the name links home; Work opens a menu of the case studies). Its main call to action, Get in touch, opens an enquiry drawer that posts to `VITE_CHRIS_API/enquiry` (**a route the API doesn't have yet**, see Known issues); Request my CV opens a CV drawer that posts to the same separate Lambda's `/resume`. It is the proof link every freelance cold email points to, so what ships here is public-facing.

It was built in a hurry from a starter template (credit in `README.md`). Phase 3a (foundations) gave it a deliberate folder architecture, written conventions (below) and a test suite; Phase 3b-2 added the design system (tokens, motion presets, atoms, molecules and a design system showcase, now public but unlisted at `/showcase`); Phase 3c ported the locked b3 prototype into the page and retired the old terminal (see Roadmap).

## Stack

- Vite 5, React 18, TypeScript (strict), Tailwind 3, Framer Motion 11, `clsx` + `tailwind-merge`, Fontsource variable fonts (Bricolage Grotesque, Figtree), preloaded by a small build plugin in `vite.config.ts`.
- pnpm (lockfile is `pnpm-lock.yaml`; `pnpm-workspace.yaml` only carries `onlyBuiltDependencies`).
- Hosted on AWS via SST v3: one `sst.aws.StaticSite` (`ChrisSite`) plus an `sst.aws.Bucket`, region `eu-west-2`, defined in `sst.config.ts`. The `production` stage is protected and retained on removal.
- ESLint 8 with `eslint-config-kentcdodds` (+ `react-hooks/rules-of-hooks`); Prettier 3 with `prettier-plugin-tailwindcss`.
- Vitest 3 + Testing Library (jsdom); config lives in `vite.config.ts` so the `@/` alias is shared.

## Code conventions

**General.** TypeScript, strict; no JavaScript source files; fix types rather than casting around them. Framer Motion for animation, respecting `prefers-reduced-motion` in anything new: every scroll story has a static fallback (finished state, no pinning). British English in visible copy, comments and docs; no connector em-dashes in visible copy. Works at phone width with no horizontal scroll (checked at 320, 390, 1440 and 2560). Keep what works working: the enquiry and CV-request flows and the single dark look must not regress. A new drawer form reuses `useValidatedForm`, `useDrawerFormState` and the drawer-form molecules rather than copying the CV form. Don't edit SST-generated files or anything under `.sst/`.

**Where things live.**

- `app/` is app-wide wiring, not a feature; it may import anything.
- `sections/<kebab-name>/` holds one page section: its layout, copy and any section-only hooks. Sections import `ui/`, `hooks/`, `lib/` and features (via `index.ts`), never `app/`.
- `features/<kebab-name>/` holds one concern end to end. Inside a feature use relative imports; from outside, import only via the feature's `index.ts`.
- `ui/`, `hooks/` and `lib/` never import from `app/`, `sections/` or `features/`.
- No import cycles.
- On a case-insensitive disk, never give two files in one folder names that differ only in case (`odometer.ts` beside `Odometer.tsx` breaks the import).

**Naming.** Components `PascalCase.tsx`, one component per file, named exports (no default exports). Hooks `useThing.ts` (`.tsx` only when they contain JSX). Helpers `camelCase.ts`. Constants `UPPER_SNAKE`. Feature folders kebab-case. Tests colocated as `Thing.test.tsx`. Prefer string-literal unions and `as const` objects to enums.

**Imports and aliases.** `@/` points at `src/`; use it across folders, and relative imports inside a feature.

**Components and hooks.** Props as an `interface ThingProps`. Logic lives in hooks; components render; the maths behind scroll and animation lives in pure `lib/` (or section) helpers with their own tests. No `window` reads during render in new code. Per-frame scroll visuals write to the DOM through refs (or set coarse state that bails out when unchanged), via `useScrollFrame`, passing the section as its `watch` element so an off-screen section costs nothing; skip writes that wouldn't change anything, and measure what only a resize can change (its `resized` flag) rather than every frame. `react-hooks/exhaustive-deps` is on.

**Context and providers.** One context per concern, inside its feature: `ThingContext.ts` (the context, its value type, and a `useThing` hook that throws outside its provider) and `ThingProvider.tsx`. Memoise the provider value. Providers are composed only in `app/AppProviders.tsx`. Use context for app-wide state only; pass props otherwise.

**Styling.** Tailwind with the design tokens; see Design system below. Use `cn` for conditional classes in new code. Don't retrofit `cn` onto existing class strings: `tailwind-merge` drops conflicting classes and can change rendering. Tailwind scans everything under `src/` (tests included), so class-like words in comments can generate CSS.

**Design system.** Built in Phase 3b-2 from the locked b3 look; the whole page uses it since 3c. The current look, Night chapters, is open: no boxed cards, outlines or filled chips. Structure comes from each chapter's full-bleed tone (`--color-tone-*`, faded in by `.chapter-tone`), type, the numbered journey (chapter and step numerals) and space. Primary actions are the only filled controls; secondary ones are lilac-underlined links (the `ghost` button variant); fields and the part picker sit on a 3:1 underline.

- **Tokens** are CSS variables in `src/ui/tokens/tokens.css`, mapped into Tailwind in `tailwind.config.ts` (`bg-surface`, `text-muted`, `border-line`, `text-body-sm`, `rounded-card`, `shadow-focus-glow`, `duration-base`, `ease-enter`, `sheet:` / `wide:` and friends). Colours are RGB channels, so opacity modifiers work (`bg-danger/10`).
- **Never raw hex in components.** Raw values live only in `tokens.css`. Chapter grounds are `tone-*`. Product mocks have their own named token groups there: `figure-*` (the Wayfinder iso faces), `chat-*` (the white brand widget), `bb-*` (the Badass Burpees screen and phone), `tenant-teal`. Arbitrary values may reference tokens (`rgb(var(--color-bb-ink))`).
- **New token keys must not shadow Tailwind defaults** (`rounded-md`, `shadow-lg`, `font-mono`… are used by live markup); `src/ui/tokens/tailwindConfig.test.ts` enforces it. When you add a font size, shadow or radius key, add it to `TOKEN_MERGE_KEYS` in `src/lib/cn.ts` too (the same test checks), or `tailwind-merge` will drop it.
- **Motion** comes from `useMotionPreset` (`src/ui/motion/`) or `@/ui/tokens/motion` (`DURATION`, `EASE`, `STAGGER`), never hard-coded durations. Every preset drops transforms and duration under `prefers-reduced-motion`; CSS transitions add `motion-reduce:transition-none`.
- **Layers:** atoms are single elements with no app knowledge; molecules compose atoms; organisms (3c) may hold behaviour. None import from `app/` or `features/`.
- **Fonts** are self-hosted Fontsource variable fonts, imported from `@/ui/tokens/fonts` by `main.tsx` and the showcase. The build injects `<link rel="preload">` for the two Latin files the first screen needs (`fontPreload.ts`, which fails the build if one goes missing).
- **Dimming:** never fade text with `opacity` (it drops below AA). An inactive step takes `tone-dim` (in `styles/index.css`), which remaps `ink` and `muted` inside it to the `dim-*` tokens (both at least 4.5:1, pinned by `tokens.test.ts`). The only thing that fades is a step's decorative numeral (`stepNumeralClasses`), which is hidden until its step is selected. Form field underlines use `line-field` (3:1).
- **Line height:** b3 set many sizes with the CSS `font` shorthand, which resets line height to `normal`; where a component must match it, use `leading-[normal]` (labels, buttons, build-lane titles).
- **Showcase:** run `pnpm dev` and open `/showcase.html` to see every token and component. Add each new component there (a section in `src/showcase/sections/`). It is a second Vite entry, built in its own pass (`vite build --mode showcase`, after the page's) so the page's bundle, CSS and font preloads are exactly what they'd be without it; the preload plugin runs only for the page. The page's CSS never carries its utilities: `tailwind.config.ts` always skips `src/showcase/**`, and the showcase imports `src/showcase/showcase.css`, which compiles the page's global styles against `tailwind.showcase.config.ts` (the same config, scanning the showcase too). Live at `/showcase`, unlisted.

**Tests.** Vitest + Testing Library. Test behaviour, not snapshots. Render through `renderWithProviders` (from `@/test/renderWithProviders`). Mock `fetch` with `vi.stubGlobal`, env with `vi.stubEnv`; `src/test/setup.ts` restores both after each test. To test under reduced motion, stub `matchMedia` to match `reduced-motion` before the first render (Framer reads it once per test file). Drive an `IntersectionObserver` by stubbing your own (see `useStepSync.test.tsx`). Test fixtures use neutral data (`Ada`, `ada@example.com`).

## The Wayfinder figure

The chapter's signature moment: an isometric drawing (pure plan-space data through one projection, `iso.ts`) that comes apart into numbered pieces. Hold these when changing it:

- **Steps:** the intro (00, takes it apart), parts 01 to 09 (each opens its own pieces; the others close up a little), the demo (10, back together). Step numbers count from 1 internally (0 is "none yet"); what shows is `numeralForStep`. The toggle overrides the step's state until the step changes. A message sent while apart shows at once and sets off once the board is whole (a quick reassembly).
- **Paint order** is re-sorted every frame (`isoDepth`). A sweep test pins that no piece or seating axis ever passes through another in any transition (apart, focus moves, phones, each live platform), so a correct order always exists: re-run it after moving any offset.
- **Legibility:** wide, the figure grows while apart (from its bottom-right corner into the left margin, as the room allows, up to 1.5x); tags are a fixed 13px on screen, lined up in a column, row or plan-aligned line per part, and a test pins that no two numbers touch, none sits on its part, no leaders cross and every badge they would cover steps aside. Measure only on resize.
- **Phones** open only the part in focus, in place, and draw off only its pipes; no toggle. The "Inside" lists are the readable twin of the tags (and the accessible one: the SVG is a described image).
- **Disclosure:** piece names stay at the level the copy and chips already disclose (the "why", never the "how"); see the anonymisation rule below.

## The physio figure

Chapter 2's figure (`src/sections/physio/`) tells the platform's tenant isolation with one `sessions` table drawn as see-through sheets, one per organisation (invented tree names: Alder, Birch, Cedar), under the SQL that reads it. The picture and the query must tell the same story at every step without the copy. Hold these when changing it:

- **Steps:** 1, the table at rest (just the table's name, every organisation's rows interleaved, no result for anyone); 2, a request signed in as Alder (`set local`, then `select * from sessions`): the policy is always on, so only Alder's sheet comes out in front while the rest stay held back behind it; 3, the policy named (row-level security) and the leak test: sign in as anyone, ask for another organisation's sessions by name (`where organisation_id = …`) and get an empty, dashed "No sessions" result. One plain line under the query says what comes back (no numbers); a visually hidden live twin says it in full.
- **State** is pure and tested: `leakTest.ts` (what each step returns, and where each sheet sits: the table, the result, or a slot in the held pile), `demo.ts` (the demo's scheduler), `flat/flatGeometry.ts` (the phone layout, with a test that nothing leaves its box in any state).
- **Two drawings, one set of spots:** `depth/` is real CSS 3D (perspective, preserve-3d) where there's room (`DEPTH_QUERY`: at least 1140px wide and 720px tall, side by side); `flat/` is the same spots without the perspective, for phones and narrow or short screens: the policy is a box holding the rest of the table as folded tabs side by side (each in its own column), the result opens out below it. Stacked (phones), the flat figure pins under the top bar on an opaque panel whose height never changes (the query keeps room for its filter and a two-line outcome, the drawing for its tallest state; a test pins it), and the picker and one button (Try, or while asking, Ask for every session again) move into the last step's card. Short phones tighten the cards, so the last one fits whole under the panel at 360×640.
- **The demo:** in step 3 the leak test plays itself (each move presses its button first: try, the empty result held long enough to read, reset, the next organisation). The visitor's move wins at once; it picks up after 10s idle. It holds while step 3 isn't active, the figure is off screen, the tab is hidden, the controls have keyboard focus, or the visitor has pressed Pause demo. The live region announces only the visitor's moves. None of it runs under reduced motion (the static step 3 state).
- **Loading:** the two drawings are their own lazy chunks, drawn only once the figure is within about a screen and a half (`useNearScreen`; at once under reduced motion), in a placeholder of their exact height, so nothing shifts when they arrive. Keeping them out of the main bundle is what holds Lighthouse mobile at 100 (in the main bundle, first paint went from 1.5s to 1.7s, scoring 99).
- **Legibility:** text you can see stays at about 14px or more on screen (the 3D tilts stay shallow; 13px is the floor on phones). The stack is decorative (`aria-hidden`, no pointer events: its 3D wrappers project over the buttons).
- **Disclosure:** no real organisations, schema, table names beyond `sessions`, or policy SQL; the brief and Chris's decisions are in `~/HQ/personal/notes/chris-site-physio-story.md`.

## Deploys

Production deploys run in GitHub Actions (`.github/workflows/deploy.yml`, `workflow_dispatch` only) under an AWS IAM role assumed via GitHub OIDC (`vars.AWS_DEPLOY_ROLE_ARN`). The workflow refuses to run off `master`, refuses if the role variable is unset, and refuses unless `ci.yml` concluded success for the exact commit; it then runs `pnpm exec sst deploy --stage production` and smoke-checks `https://chris-tregaskis.uk/` (200 + the expected `<title>`). One deploy at a time; a running deploy is never cancelled.

- **Standing permission:** Claude may trigger the production deploy for this repo **only when CI on that commit is green**. Granted by Chris on 30 Oct 2026; it covers **this repo only** and does not generalise.
- **The sequence Claude follows** (after pushing to `master` and resyncing HQ):
  1. `gh run list --workflow ci.yml --commit "$(git rev-parse HEAD)" --limit 1` — find CI for the commit.
  2. `gh run watch <ci-run-id> --exit-status` — confirm it concluded success. If not green, stop: fix, don't deploy.
  3. `gh workflow run deploy.yml --ref master` — trigger. (Deliberately not on the allow-list, so each deploy is a visible, prompted action.)
  4. `gh run list --workflow deploy.yml --limit 1` then `gh run watch <deploy-run-id> --exit-status` — watch it through.
  5. `curl -sS https://chris-tregaskis.uk/ | grep '<title>'` — confirm live, and eyeball the change.
