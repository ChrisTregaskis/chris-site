# chris-site — the charter

This file orients any Claude session that opens this repo. Read it first, then `CLAUDE.local.md` (gitignored, machine-local) for the scratch pad, HQ sync rule and the named anonymisation list.

## What this is

Chris Tregaskis's portfolio site, served at `chris-tregaskis.uk` (with `www.` redirecting). One long-scrolling React page in one light look, Drawing office (no theme switch; the site drawn as a set of engineering drawings): a hero, three numbered case studies, each on its own full-bleed shade of the drafting paper that fades into the next (Wayfinder with its interactive isometric figure, which comes apart into numbered pieces part by part, its live chat demo and How it was built lane; a physio and wellness platform, told as rings round its data that draw themselves on ring by ring, each with a journey the visitor can send through it; Badass Burpees, a set of 100 counted out by scroll in huge type and told in the app's own spoken calls), About and Contact, under a sticky top bar (the name links home; Work opens a menu of the case studies; below `wide`, a Menu button opens the same links, Get in touch and Request my CV full screen). Its main call to action, Get in touch, opens an enquiry drawer that posts to `VITE_CHRIS_API/enquiry` (**a route the API doesn't have yet**, see Known issues); Request my CV opens a CV drawer that posts to the same separate Lambda's `/resume`. It is the proof link every freelance cold email points to, so what ships here is public-facing.

It was built in a hurry from a starter template (credit in `README.md`). Phase 3a (foundations) gave it a deliberate folder architecture, written conventions (below) and a test suite; Phase 3b-2 added the design system (tokens, motion presets, atoms, molecules and a design system showcase, now public but unlisted at `/showcase`); Phase 3c ported the locked b3 prototype into the page and retired the old terminal (see Roadmap).

## Stack

- Vite 5, React 18, TypeScript (strict), Tailwind 3, Framer Motion 11, `clsx` + `tailwind-merge`, Fontsource fonts (Newsreader and Instrument Sans, both variable, preloaded by a small build plugin in `vite.config.ts`; IBM Plex Mono at 400 and 500).
- pnpm (lockfile is `pnpm-lock.yaml`; `pnpm-workspace.yaml` only carries `onlyBuiltDependencies`).
- Hosted on AWS via SST v3: one `sst.aws.StaticSite` (`ChrisSite`) plus an `sst.aws.Bucket`, region `eu-west-2`, defined in `sst.config.ts`. The `production` stage is protected and retained on removal.
- ESLint 8 with `eslint-config-kentcdodds` (+ `react-hooks/rules-of-hooks`); Prettier 3 with `prettier-plugin-tailwindcss`.
- Vitest 3 + Testing Library (jsdom); config lives in `vite.config.ts` so the `@/` alias is shared.

## Code conventions

**General.** TypeScript, strict; no JavaScript source files; fix types rather than casting around them. Framer Motion for animation, respecting `prefers-reduced-motion` in anything new: every scroll story has a static fallback (finished state, no pinning). British English in visible copy, comments and docs; no connector em-dashes in visible copy. Works at phone width with no horizontal scroll (checked at 320, 390, 1440 and 2560). Keep what works working: the enquiry and CV-request flows and the single Drawing office look must not regress. A new drawer form reuses `useValidatedForm`, `useDrawerFormState` and the drawer-form molecules rather than copying the CV form. Don't edit SST-generated files or anything under `.sst/`.

**Where things live.**

- `app/` is app-wide wiring, not a feature; it may import anything.
- `sections/<kebab-name>/` holds one page section: its layout, copy and any section-only hooks. Sections import `ui/`, `hooks/`, `lib/` and features (via `index.ts`), never `app/`.
- `features/<kebab-name>/` holds one concern end to end. Inside a feature use relative imports; from outside, import only via the feature's `index.ts`.
- `ui/`, `hooks/` and `lib/` never import from `app/`, `sections/` or `features/`.
- No import cycles.
- On a case-insensitive disk, never give two files in one folder names that differ only in case (`odometer.ts` beside `Odometer.tsx` breaks the import).

**Naming.** Components `PascalCase.tsx`, one component per file, named exports (no default exports). Hooks `useThing.ts` (`.tsx` only when they contain JSX). Helpers `camelCase.ts`. Constants `UPPER_SNAKE`. Feature folders kebab-case. Tests colocated as `Thing.test.tsx`. Prefer string-literal unions and `as const` objects to enums.

**Imports and aliases.** `@/` points at `src/`; use it across folders, and relative imports inside a feature.

**Components and hooks.** Props as an `interface ThingProps`. Logic lives in hooks; components render; the maths behind scroll and animation lives in pure `lib/` (or section) helpers with their own tests. No `window` reads during render in new code. Per-frame scroll visuals write to the DOM through refs (or set coarse state that bails out when unchanged), via `useScrollFrame`, passing the section as its `watch` element so an off-screen section costs nothing; skip writes that wouldn't change anything, and measure what only a resize can change (its `resized` flag) rather than every frame. `react-hooks/exhaustive-deps` is on.

**Context and providers.** One context per concern, inside its feature: `ThingContext.ts` (the context, its value type, and a `useThing` hook that throws outside its provider) and `ThingProvider.tsx`. Memoise the provider value. Providers are composed only in `app/AppProviders.tsx`. Use context for app-wide state only; pass props otherwise.

**Styling.** Tailwind with the design tokens; see Design system below. Use `cn` for conditional classes in new code. Don't retrofit `cn` onto existing class strings: `tailwind-merge` drops conflicting classes and can change rendering. Tailwind scans everything under `src/` (tests included), so class-like words in comments can generate CSS.

**Design system.** Built in Phase 3b-2 from the locked b3 look; the whole page uses it since 3c. The current look, Drawing office, sets the site as a set of engineering drawings: cool drafting paper (`surface`, with white `sheet` for what floats over it: menus, the drawers), graphite and ink (three text roles, `ink`, `muted` and `dim-muted`; line work in `line`, `line-strong` and `line-hover`), one red pen (`accent`, vermilion) and a checker's highlighter (`marker`). It is open, with as few boxes as possible: no boxed cards, outlines, filled chips or glass blur; the form failure banner is a red-pen rule down its side, not a bordered box; shadows are neutral, small, and only on what floats (menus, the drawers, the chat widget). Structure comes from each chapter's full-bleed paper (`--color-tone-*`, faded in by `.chapter-tone`, with a hairline across the content where the chapter starts), type, the numbered journey (chapter and step numerals) and space. Primary actions are the only filled controls (the red pen, inked in to graphite when pressed); secondary ones are ink links on a pencil underline that the red pen takes over on hover (the `ghost` button variant); fields and the part picker sit on a 3:1 underline. Corners are only softened (2 to 4px; no pill buttons, pills only in the brand chat widget's own design and for dots), and labels are sentence case, never uppercase. No decorative grids or parallax: every mark on the page means something. The look was shaped with the unslop passes (spacing, colour, icons, type, layout, details, visuals, motion): unslop by Damir Sokolovsky (@heydamir), CC BY 4.0.

- **Tokens** are CSS variables in `src/ui/tokens/tokens.css`, mapped into Tailwind in `tailwind.config.ts` (`bg-surface`, `text-muted`, `border-line`, `text-body-sm`, `rounded-card`, `shadow-focus-glow`, `duration-base`, `ease-enter`, `sheet:` / `wide:` and friends). Colours are RGB channels, so opacity modifiers work (`bg-danger/10`).
- **Never raw hex in components.** Raw values live only in `tokens.css`. Chapter grounds are `tone-*` (all the plain paper; the surface's chapter tones point them at the `--color-paper-*` shades, see Surface). Product mocks have their own named token groups there: `figure-*` (the Wayfinder iso faces), `chat-*` (the white brand widget), `tenant-teal`. Arbitrary values may reference tokens (`rgb(var(--color-bb-ink))`).
- **New token keys must not shadow Tailwind defaults** (`rounded-md`, `shadow-lg`, `font-mono`… are used by live markup); `src/ui/tokens/tailwindConfig.test.ts` enforces it. When you add a font size, shadow or radius key, add it to `TOKEN_MERGE_KEYS` in `src/lib/cn.ts` too (the same test checks), or `tailwind-merge` will drop it.
- **Motion** comes from `useMotionPreset` (`src/ui/motion/`) or `@/ui/tokens/motion` (`DURATION`, `EASE`, `STAGGER`), never hard-coded durations. Every preset drops transforms and duration under `prefers-reduced-motion`; CSS transitions add `motion-reduce:transition-none`.
- **Layers:** atoms are single elements with no app knowledge; molecules compose atoms; organisms (3c) may hold behaviour. None import from `app/` or `features/`.
- **Colour roles:** the red pen is the one accent, and `signal` is the same red ("what's happening now" never gets a second hue). It marks the primary action, the focus ring, the step in focus (its numeral, its part in the figure, its pressed piece), the selected option in the part picker, the Burpees call being made, a pulse, a wall that holds, and form errors (`danger`, `danger-ink`). Everything else, the chrome included, stays graphite. The highlighter (`marker`) marks what a journey or message has passed through and a detail picked out; it goes over line work (multiplied, so the ink shows through) or behind ink text, never as a text colour. Don't add a second accent hue.
- **Contrast floors** (pinned by `src/ui/tokens/tokens.test.ts`, and on every chapter paper by `src/features/surface/tones.test.ts`): every text role at 4.5:1 on every paper it can sit on. The red pen as text is the tightest pair (4.95:1 on the paper, 4.57:1 on Burpees's, the deepest tone), so no tone may go deeper. Form field underlines (`line-field`) and drawn edges hold 3:1; the fainter pencil (`line-hover`, stepped-back edges and a text link's underline) sits exactly at 3.0:1 by design, and is firmed on the chapter tones (`--color-paper-line-hover`) so it keeps 3:1 there. Check any new colour against the deepest paper.
- **Fonts** are self-hosted Fontsource fonts, imported from `@/ui/tokens/fonts` by `main.tsx` and the showcase. Newsreader (variable, with optical sizes; `font-display`) sets the headlines and the ordering numbers (chapter and step numerals, the picker's and Work menu's numbers, set light with lining figures), and the Burpees count and calls. Instrument Sans (variable; `font-body`) sets everything read or pressed. IBM Plex Mono (400 and 500; `font-code`) belongs only to the drawings: part balloons, piece tags, ring names, the Inside lists' numbers, the demo and journey traces, and the chapter rail's count. The build injects `<link rel="preload">` for the two Latin files the first screen needs (Newsreader and Instrument Sans; `fontPreload.ts`, which fails the build if one goes missing); the mono loads when the first drawing, trace or rail renders.
- **Dimming:** never fade text with `opacity` (it drops below AA). An inactive step takes `tone-dim` (in `styles/index.css`), which remaps `ink` and `muted` inside it to the `dim-*` tokens (both at least 4.5:1, pinned by `tokens.test.ts`). The only thing that fades is a step's decorative numeral (`stepNumeralClasses`), which is hidden until its step is selected; entrances are different (a physio step's words fade in at full strength while its ring is the one shown, and out again as they leave). Form field underlines use `line-field` (3:1).
- **Scroll feedback** is drawn in the red pen, in one vocabulary of hollow circles on hairlines. The How it was built lane (`BuildStory`): each stage a hollow circle on a hairline that the red line fills, each circle turning to a ringed bullet (red edge, a ring of paper, red core) with a brief grow as the line reaches it; under reduced motion the lane is lit from the start, with no grow. From `xl` (1280px; closer, it crowds the content) each case study carries a `ChapterRail` in the same terms: its count ("1/3", in the mono) over a hollow circle and a hairline rail, centred on the window's height, that the red pen fills as the chapter is read; the circle becomes a ringed bullet once it's finished. At every width, the dead-zone cues: a red spark in a ring of paper riding the build lane's line while it's pinned (`.build-head`) and the Burpees count straining through the last reps (`.set-strain`). All CSS scroll-driven animation, opacity and transforms only, drawn only where supported; no cues under reduced motion, where the rail fills in quarters.
- **Line height:** b3 set many sizes with the CSS `font` shorthand, which resets line height to `normal`; where a component must match it, use `leading-[normal]` (labels, buttons, build-lane titles).
- **Showcase:** run `pnpm dev` and open `/showcase.html` to see every token and component. Add each new component there (a section in `src/showcase/sections/`). It is a second Vite entry, built in its own pass (`vite build --mode showcase`, after the page's) so the page's bundle, CSS and font preloads are exactly what they'd be without it; the preload plugin runs only for the page. The page's CSS never carries its utilities: `tailwind.config.ts` always skips `src/showcase/**`, and the showcase imports `src/showcase/showcase.css`, which compiles the page's global styles against `tailwind.showcase.config.ts` (the same config, scanning the showcase too). Live at `/showcase`, unlisted.
- **Surface** (`src/features/surface/`, mounted by `<Surface />` in `App.tsx`): the paper behind the content, in two layers, as `SURFACE_DEFAULTS` (`settings.ts`) sets them. **Chapter tones:** `data-tones` on the root points each chapter's `--color-tone-*` at its `--color-paper-*` shade, one cool paper family stepping a little deeper into the work (Burpees the deepest) and back out, the plate fading in from the chapter before over 360px. **The pencil mesh:** a seeded, triangulated survey net on a canvas anchored to the page (`MeshCanvas`, so it scrolls with the paper, never fixed to the window), between the chapter plates and the content, `aria-hidden` and `pointer-events: none`. Its facets are lit from the upper left and press in under a mouse; a pencil line runs along every edge, each edge drawn once so lines never darken each other. It lies only at the page's ends (`reach.ts`): full in the hero, faded out before Wayfinder's numeral, absent through all three case studies, back from half a hero before About and full through Contact, a spatial fade measured from the sections' real positions. **Quiet zones:** it steps back round the drawings (the Wayfinder figure, the physio rings' room, the Burpees count, and anything marked `data-mesh-quiet`, today the Burpees calls and Done), per facet and through a soft mask, measured every frame it draws and repainted when a quiet element moves or arrives without a scroll. **Text protection:** behind every line of text where it lies, the pencil thins to a solved `keep` (`strength.ts`) through a soft mask (one box per line fragment, padded and blurred, from `textMask.ts`; re-measured on resize, layout and font changes, never per frame); the facets are left whole. **The drawers:** a still, faint mesh gathered in the empty paper at their foot, through `Drawer`'s `surface` slot (`DrawerSurface`, `DrawerMesh`), with fields, buttons, errors and the alert kept bare. **Loading and fallbacks:** the mesh's code (page and drawers) is its own lazy chunks, fetched 400ms after the load event once the browser is idle (`useAfterLoad`, as the Burpees set does, to hold Lighthouse mobile at 100); the canvas then eases in, or just appears under reduced motion. On touch screens and under reduced motion the mesh holds still (`effectiveMesh`); phones get it a touch fainter.
- **What the mesh must never do:** lie under a diagram or over the case studies; take any text below its AA floor (the facets' shadow ceiling, `MAX_SHADOW` in `meshLook.ts` times the strength, and the pencil's `keep` behind text are solved for it, and `tones.test.ts` checks every measured line of text at 1440 and 390 for its own role; at Medium and Strong the red pen fails AA without text protection, so Protect text never ships off); move on touch or under reduced motion; cost the first paint; scroll sideways or lengthen the page (the layer is floored to the page's height). A new drawing in its reach gets `data-mesh-quiet`; the three existing drawings are found by selectors (`QUIET_SELECTORS` in `useMeshCanvas.ts`), so changing their markup means checking that list.
- **Dev panel** (`src/features/dev-panel/`): a dev-only panel at the bottom right under `pnpm dev`, a group of controls per experiment, each also a URL parameter written back on every change, so a state can be reloaded or shared (Surface's: `?tones=1&mesh=pointer&lines=1&reach=ends&strength=medium&protect=1&drawer=mesh&drawerStrength=faint`). Reuse it for any future visual experiment: define the settings once beside the experiment with `defineDevSettings(defaults, import.meta.env.DEV ? group : null)` (a boolean gets a checkbox, a string union radio buttons; `inactive` greys a control out and `useNote` adds a live line) and read them with `useDevSettings`. Parameter names are the keys, so keep them unique across experiments. A production build uses the defaults and nothing else: `<DevPanelSlot />` is null outside dev, the URL is never read, and the panel and every label are compiled out, absent from `dist/`.

**Tests.** Vitest + Testing Library. Test behaviour, not snapshots. Render through `renderWithProviders` (from `@/test/renderWithProviders`). Mock `fetch` with `vi.stubGlobal`, env with `vi.stubEnv`; `src/test/setup.ts` restores both after each test. To test under reduced motion, stub `matchMedia` to match `reduced-motion` before the first render (Framer reads it once per test file). Drive an `IntersectionObserver` by stubbing your own (see `useStepSync.test.tsx`). Test fixtures use neutral data (`Ada`, `ada@example.com`).

## Deploys

Production deploys run in GitHub Actions (`.github/workflows/deploy.yml`, `workflow_dispatch` only) under an AWS IAM role assumed via GitHub OIDC (`vars.AWS_DEPLOY_ROLE_ARN`). The workflow refuses to run off `master`, refuses if the role variable is unset, and refuses unless `ci.yml` concluded success for the exact commit; it then runs `pnpm exec sst deploy --stage production` and smoke-checks `https://chris-tregaskis.uk/` (200 + the expected `<title>`). One deploy at a time; a running deploy is never cancelled.

- **Standing permission:** Claude may trigger the production deploy for this repo **only when CI on that commit is green**. Granted by Chris on 30 Oct 2026; it covers **this repo only** and does not generalise.
- **The sequence Claude follows** (after pushing to `master` and resyncing HQ):
  1. `gh run list --workflow ci.yml --commit "$(git rev-parse HEAD)" --limit 1` — find CI for the commit.
  2. `gh run watch <ci-run-id> --exit-status` — confirm it concluded success. If not green, stop: fix, don't deploy.
  3. `gh workflow run deploy.yml --ref master` — trigger. (Deliberately not on the allow-list, so each deploy is a visible, prompted action.)
  4. `gh run list --workflow deploy.yml --limit 1` then `gh run watch <deploy-run-id> --exit-status` — watch it through.
  5. `curl -sS https://chris-tregaskis.uk/ | grep '<title>'` — confirm live, and eyeball the change.
  6. On failure: `gh run view <run-id> --log-failed` and report it with the output. Never retry by running `sst deploy` locally.
- Claude never touches AWS credentials, profiles or IAM, and never runs `sst deploy` locally. An `AccessDenied` in the deploy log is reported to Chris with the action it names; he changes the role policy.
- Chris's manual fallback is unchanged: `pnpm sst:deploy:prod` with his AWS profile.
